Two things to know before you design a daughterboard

  • The Arduino header has no analog inputs. A0–A3 are not connected; only A4/A5 are, and those are the I²C pins.
  • mikroBUS socket 3 has MISO unconnected. It transmits only — receiving needs a hand-wired link.

02

Two paths, equal in quality

The TESAIoT Firmware Stack ships as two project templates. Choose by how you work, not by how advanced you are — both use the same libraries, the same hardware and the same documentation.

ModusToolbox™

Compiled firmware, every byte under your control

ModusToolbox™ is Infineon's official development toolchain for PSoC™. It brings the board BSP, the hardware libraries, a graphical device configurator and the Arm GCC compiler. The project you get is plain C, compiled onto all three cores.

  • Microsecond-level timing control — no interpreter between your code and the hardware
  • Configure the device graphically — clocks, pins and peripherals through the Device Configurator
  • Instruction-level debugging — breakpoints, registers and single-stepping over KitProg
  • Smallest RAM and flash footprint — which leaves the most room for Edge AI models

Suits: products going to manufacture, latency-critical work, battery-constrained designs.

ModusToolbox™ + MicroPython

Write Python on the board, see it the moment you press Enter

Everything in the first path, plus MicroPython embedded in the firmware from the start, with modules we wrote ourselves for the sensors, the display, Wi-Fi, MQTT, the HSM and Edge AI — plug in USB and start talking to the hardware.

  • No compile, no flash — edit and run; the experiment loop drops from minutes to seconds
  • A live REPL to the board — read a sensor line by line while you are chasing a problem
  • Python files live on the board — a 52 MB file system, so the code stays with the device
  • Mix C and Python — C where it must be fast, Python where it changes often

Suits: teaching, prototyping, sensor experiments, and work whose requirements are still moving.

An SDK that gives you both source and signed libraries

What you receive is not one opaque binary. It is code you can read, nearly all of it, beside six prebuilt libraries carrying a digital signature — and a script that lets you verify them yourself, from the first minute after you unzip.

  • ~237,000 lines of C open to read — every screen, every driver, the whole BSP
  • 6 prebuilt libraries exporting 284 public API entries, with an api.txt that tells the truth
  • 40 worked examples that genuinely compile — not documentation code that does not build
  • 35 tutorial chapters in the order you actually meet the work, in both languages
  • Verify the signature yourself — ./verify.sh checks every file against a signed manifest

03

Security stated at the strength we can prove

We prove it on real hardware and write down only what we proved. Where something is not enforced, we say it is not enforced.

Proven on hardware

OPTIGA™ Trust M

  • Key pair generated inside the chip — the private key never leaves it
  • Certificate requested by CSR and returned over MQTT with TLS
  • Protected Update with manifest verification in silicon, which fails closed
  • Mutual TLS with the key staying inside the chip throughout

OPTIGA is a plug-in module, not soldered to the board — ordered separately and fitted at address 0x30.

Not enforced — and we say so plainly

What is contractual rather than mechanical

  • The licence check is compiled into no image. The commercial restriction is a contract, not a technical boundary.
  • The Edge AI model signature is verified but not enforced — a model that fails verification still loads.
  • BLE pairing is currently Just Works, with no authentication required (BLE is off by default).
  • The factory certificate identifies a chip, not a device — binding identity has to happen at the broker.

04

Edge AI that runs on day one

The engine sits on the Cortex®-M55 beside the Ethos™-U55 NPU. It arrives with DEEPCRAFT™ models that work out of the box, and empty slots for models of your own.

SIX MODEL SLOTS

  • motionrunning
  • audiorunning
  • radarrunning
  • coughempty
  • alarmempty
  • sirenempty

The first three carry models that ship with the kit. The other three are deliberately empty — Imagimob's Ready Models are governed by their own licence, so we do not redistribute them, but the slots are open for you to fit your own.

FOUR WAYS TO ADD YOUR OWN MODEL

  1. Register at run time Call ai_engine_register() — no slot needed, and no rebuild of our engine.
  2. Export from DEEPCRAFT™ Studio Overwrite the generated model source and rename the four entry points.
  3. Drop in your own library Name it to the pattern and the Makefile links it for you.
  4. Write your own runtime Anything behind those four functions — TFLite, or something of your own.

Every route works without touching the code we keep closed, and without waiting for a new library from us.
