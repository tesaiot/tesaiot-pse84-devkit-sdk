Learning goal

Distinguish a command from a request. stop() is a command; unload() is a request the engine may refuse; stage_load() has no acknowledgement at all — you confirm it by watching the registry count rise. Each has a different verification path and this chapter walks all three.

Firmware sequence

Stop. edge_ai.stop() sends STOP over the model link and then makes a best-effort idle confirm. CM55 calls ai_engine_stop() — a request; ai_engine_active() == -1 is the confirmation — and then walks the sensor rate back down** to the dashboard cadence:

ai_engine_stop(); /* a request, not yet a fact */
ai_engine_set_sensor_rate(100u); /* back to the 10 Hz dashboard cadence */
/* ... later: ai_engine_active() == -1 confirms the stop */
ai_engine_stop
void ai_engine_stop(void)
Stop the active model (idempotent); pair with a sensor-rate walk-down.
ai_engine_set_sensor_rate
void ai_engine_set_sensor_rate(uint32_t interval_ms)
Set the accelerometer feed interval; call it on its own, from one owner.

The rate call is mandatory: without it the accelerometer stays at 50 Hz and starves the dashboard sensors.

Unload. edge_ai.unload(i) is "a request, not a command": send stop() first, then read edge_ai.diag() to see whether it completed or was refused. The C side uses the same pair of counters, with the baseline taken before the request:

const uint32_t done0 = ai_engine_unload_done();
const uint32_t refused0 = ai_engine_unload_refused();
ai_engine_unload(idx); /* asynchronous */
/* ... later: done - done0 == 1 -> released; refused - refused0 == 1 -> refused */
ai_engine_unload
void ai_engine_unload(uint32_t idx)
Asynchronous unload request — refused unless the engine is idle.
ai_engine_unload_done
uint32_t ai_engine_unload_done(void)
Cumulative count of completed unloads; read as a pair with refused.
ai_engine_unload_refused
uint32_t ai_engine_unload_refused(void)
Cumulative count of refused unloads; read with ai_engine_unload_done().

The request is honoured only when the engine is idle — the stop must have been confirmed (ai_engine_active() == -1), not merely requested — and the model is loaded and has a finalize(). Otherwise it is refused and counted. After an unload, the next select of that model reloads it from scratch.

Staged model. edge_ai.stage_load(...) sends MODEL_LINK_CMD_LOAD_STAGED; CM55 handles it in task context, never in the pipe callback, because ai_model_staged_load() allocates from the CM55 heap the display also draws from:

int idx = ai_model_staged_load(header_addr); /* task context only */
if (idx < 0) {
/* -1..-7, listed in ai_model_staged.h; ai_model_staged_last_rc() keeps it */
}
ai_model_staged_load
int ai_model_staged_load(uint32_t header_addr)
Build and register a model CM33 staged in shared memory; task context only.

There is no ack event; the MicroPython side confirms by watching the registry count rise.

Step by step

Step 1 — Stop a running model

>>> edge_ai.select(0); edge_ai.stop()
>>> edge_ai.active()
-1

What you should observe. active() returns −1 once the stop has been confirmed. On screen the badge goes Stopped (not Failed, because stack_words() is non-zero). Dashboard sensor rows resume their normal cadence within ~2 s.

Step 2 — Unload while running: watch the refusal

>>> edge_ai.select(0)
True
>>> before = edge_ai.diag()['unload_refused']
>>> edge_ai.unload(0)
>>> edge_ai.diag()['unload_refused'] - before
1

What you should observe. unload_refused increments by one and unload_done does not move. The engine was not idle, so the request was refused and counted — that counter is the answer.

Step 3 — Unload after stop: watch the completion

>>> edge_ai.stop()
>>> before = edge_ai.diag()['unload_done']
>>> edge_ai.unload(0)
>>> edge_ai.diag()['unload_done'] - before
1

What you should observe. unload_done increments. The next select(0) takes the full cold-load path again (up to 15 s), which is the intended effect. Poll the pair unload_done/unload_refused together; reading one alone tells you nothing.

Step 4 — Stage a model and confirm by observation

>>> n0 = len(edge_ai.models())
>>> edge_ai.stage_load(...) # per the edge_ai module reference
>>> len(edge_ai.models()) - n0
1

What you should observe. The registry count rises by one. That is the only confirmation there is. If it does not rise, read edge_ai.diag() for the staged counters — staged_rejects and staged_last_rc come as a pair, and cm55_heap_free gives the CM55 heap headroom.

Step 5 — Make the staged model join a set

>>> edge_ai.set_define(253, [0, n0]) # n0 = the new row's index

What you should observe. The Q_SET read-back lists both members. set_define() with the new row's registry index is the supported way to put an uploaded model in a set; do not rely on giving it the name of a compiled member.

Traps

Warning
Never call ai_engine_resume_sensor() right after ai_engine_set_sensor_rate(). Both requests are asynchronous, and a resume issued while a rate request is still in flight can cancel it: CM33 then pauses the sensor push instead of changing its rate. set_sensor_rate() already resumes the push. resume_sensor has no caller anywhere in shipped firmware; the authored example is a standalone send with the anti-pattern boxed:
__attribute__((used))
static void bento_ex_ai_engine_resume_sensor(void)
{
/* WRONG — the two requests can cancel each other (see the box):
*
* ai_engine_set_sensor_rate(100u); // rate request, in flight...
* ai_engine_resume_sensor(); // ...can cancel it -> PAUSE
*
* RIGHT — set_sensor_rate alone already resumes the sensor push:
*
* ai_engine_set_sensor_rate(100u); // walk down to dashboard rate
*
* RIGHT — resume on its own, with no rate change in flight
* (page-leave path, no rate change wanted): */
ai_engine_resume_sensor();
}
Warning
Give sensor-rate changes one owner. Two tasks calling set_sensor_rate()/resume_sensor() without knowing about each other can cancel each other the same way. The shipped firmware decides the rate in one place; your code should too.
Stop is confirmed, not requested. An unload() issued in the same breath as stop() will usually be refused because the engine has not yet confirmed the stop. Check active() == -1 first.
