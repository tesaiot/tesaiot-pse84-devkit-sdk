Learning goal

Distinguish a command from a request. stop() is a command; unload() is a request the engine may refuse; stage_load() has no acknowledgement at all — you confirm it by watching the registry count rise. Each has a different verification path and this chapter walks all three.

Real firmware sequence

Stop. edge_ai.stop() (modedgeai.c:543-552) sends EDGE_AI_CMD_STOP and then makes a best-effort idle confirm. CM55 clears s_running, calls ai_engine_stop() — which only sets s_active = -1 (ai_engine.c:1864) — and then walks the sensor rate down:

Lifted from deepcraft_task.c:679-690 (compiled into the prebuilt archive; not shipped as source).

deepcraft_task.c:682-686 records why the rate call is mandatory: without it the accelerometer stayed pinned at 50 Hz and starved the dashboard sensors. The rate is also re-asserted every 2 s as a self-healing measure:

Origin
Lifted from deepcraft_task.c:811-823 (compiled into the prebuilt archive; not shipped as source).

Unload. edge_ai.unload(i) (modedgeai.c:406-419; contract at :400-405: "A request, not a command… Send `stop()` first, then read `edge_ai.diag()` to see whether it completed or was refused"). CM55 queues it:

Origin
Lifted from deepcraft_task.c:691-695 (compiled into the prebuilt archive; not shipped as source).

The inference task services it at the top of a pass (ai_engine.c:1401-1416) and requires s_current < 0 && s_active < 0 — the stop must have been observed, not merely requested — plus a model whose s_model_ready flag is set and which has a finalize. It then bumps s_unload_done, otherwise s_unload_refused. Why unload exists at all (ai_engine.c:1255-1260): a DEEPCRAFT finalize() frees the model but leaves its handle dangling, and enqueue() keeps returning success; clearing s_model_ready forces the next select down the cold-init path "instead of feeding a corpse".

Staged model. edge_ai.stage_load(...) sends MODEL_LINK_CMD_LOAD_STAGED; CM55 handles it in task context, never in the pipe callback:

Origin
Lifted from deepcraft_task.c:696-715 (compiled into the prebuilt archive; not shipped as source).

deepcraft_task.c:700-711 gives the reason: mtb_ml_model_init() allocates from the LVGL heap and registration takes a critical section. Validation-before-trust is ai_model_staged.c:452-470. There is no ack event; the MicroPython side loops on the registry count (modedgeai.c:808-828).

Step by step

Step 1 — Stop a running model

>>> edge_ai.select(0); edge_ai.stop()
>>> edge_ai.active()
-1

What you should observe. active() returns −1 once the inference task has observed the stop. On screen the badge goes CHIP_STOPPED (page_edge_ai.c:1338 — CHIP_STOPPED, not CHIP_FAIL, because stack_words() is non-zero). Dashboard sensor rows resume their normal cadence within ~2 s.

Step 2 — Unload while running: watch the refusal

>>> edge_ai.select(0)
True
>>> before = edge_ai.diag()['unload_refused']
>>> edge_ai.unload(0)
>>> edge_ai.diag()['unload_refused'] - before
1

What you should observe. unload_refused increments by one and unload_done does not move. The engine was not idle, so the request was refused and counted — that counter is the answer.

Step 3 — Unload after stop: watch the completion

>>> edge_ai.stop()
>>> before = edge_ai.diag()['unload_done']
>>> edge_ai.unload(0)
>>> edge_ai.diag()['unload_done'] - before
1

What you should observe. unload_done increments. The next select(0) takes the full cold-load path again (up to 15 s), which is the intended effect. Poll the pair unload_done/unload_refused together (deepcraft_task.c:377-378 → modedgeai.c:452-455); reading one alone tells you nothing.

Step 4 — Stage a model and confirm by observation

>>> n0 = len(edge_ai.models())
>>> edge_ai.stage_load(...) # per the edge_ai module reference
>>> len(edge_ai.models()) - n0
1

What you should observe. The registry count rises by one. That is the only confirmation there is. If it does not rise, read edge_ai.diag() for the staged counters — staged_rejects and staged_last_rc are exported as a pair (deepcraft_task.c:380-382), staged_heap_free is an ISR-safe read (:379).

Step 5 — Make the staged model join a set

>>> edge_ai.set_define(253, [0, n0]) # n0 = the new row's index

What you should observe. The Q_SET read-back lists both members. Without set_define, an uploaded model can join a compiled set only by impersonating one by name (ai_engine.c:1092-1127), and set_wants() does not stop at the first match, so both would be fed and both would publish (modedgeai.c:855-859).

Traps

Warning
Never call ai_engine_resume_sensor() right after ai_engine_set_sensor_rate(). They share one CY_SECTION_SHAREDMEM buffer, s_rate_msg, and Cy_IPC_Pipe_SendMessage is asynchronous; op=1's leading memset zeroes an in-flight op=2 and CM33 reads PAUSE (ai_engine.c:522-536). resume_sensor has no caller anywhere in shipped firmware; the authored example is a standalone send with the anti-pattern boxed:
__attribute__((used))
static void bento_ex_ai_engine_resume_sensor(void)
{
/* WRONG — the shared-buffer hazard (see the box above):
*
* ai_engine_set_sensor_rate(100u); // op=2, in flight...
* ai_engine_resume_sensor(); // memset kills it -> PAUSE
*
* RIGHT — set_sensor_rate alone already resumes the push task:
*
* ai_engine_set_sensor_rate(100u); // walk down to dashboard rate
*
* RIGHT — resume as a standalone message, nothing else in flight
* on s_rate_msg (page-leave path, no rate change wanted): */
ai_engine_resume_sensor();
}
Warning
set_sensor_rate must be the only IPC sender on that buffer. All five shipped call sites go through dc_desired_sensor_rate().
Stop is observed, not requested. An unload() issued in the same breath as stop() will usually be refused because the inference task has not yet run a pass with s_current < 0. Check active() == -1 first.
