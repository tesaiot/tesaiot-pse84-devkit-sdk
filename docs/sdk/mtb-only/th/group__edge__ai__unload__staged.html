Detailed Description

ฟังก์ชัน 8 ตัว: คำขอ unload แบบอะซิงโครนัสพร้อมตัวนับ 2 ตัวของมัน และตัวโหลด ณ เวลาทำงาน (ai_model_staged.h) พร้อมตัวนับ 4 ตัวของมัน ทั้งสองครึ่งใช้แนวออกแบบเดียวกัน: ไม่มี ack event — การยืนยันทำด้วยการสังเกตค่าตัวนับ

◆ ai_engine_unload()

void ai_engine_unload ( uint32_t idx)

คำขอ unload แบบอะซิงโครนัส — จะถูกปฏิเสธ เว้นแต่ engine ว่างอยู่

Release a run-time model and free what it owns. Asynchronous: the request is serviced in the inference task and REFUSED unless the engine is idle, because a parallel set dequeues every member on every pass. The two counters below are how a caller learns which happened.

ข้อกำหนดการเรียกใช้
เป็นคำขอ ไม่ใช่คำสั่ง และเป็นแบบอะซิงโครนัส คำขอนี้ถูกให้บริการที่ต้นรอบการอนุมาน (ai_engine.c:1401-1416) และจะถูกปฏิเสธ เว้นแต่ engine ว่างอยู่ — คือต้องเป็นทั้ง s_current < 0 และ s_active < 0 กล่าวคือ inference task ต้องสังเกตเห็นการหยุดแล้ว ไม่ใช่แค่มีการร้องขอให้หยุด ให้วนถาม ai_engine_unload_done() / ai_engine_unload_refused() เพื่อทราบว่าเกิดอย่างใดขึ้น (ฝั่ง MicroPython: edge_ai.stop() แล้ว edge_ai.unload(i) แล้วจึงอ่าน edge_ai.diag()) เหตุที่เรื่องนี้สำคัญ: finalize() ของ DEEPCRAFT คืนหน่วยความจำของโมเดลไป แต่ปล่อย handle ของมันค้างไว้ และ enqueue() ก็ยังคืนค่าว่าสำเร็จอยู่เรื่อย ๆ — การล้าง s_model_ready[idx] คือสิ่งที่บังคับให้ select ครั้งถัดไปเดินลงเส้นทาง cold-init "instead of feeding a corpse" (ai_engine.c:1255-1260)

◆ ai_model_staged_load()

int ai_model_staged_load ( uint32_t header_addr)

สร้างและลงทะเบียนโมเดลที่ CM33 staged ไว้ในหน่วยความจำร่วม; เรียกได้จาก task context เท่านั้น

ข้อกำหนดการเรียกใช้
สร้างโมเดลจาก manifest ที่ CM33 staged ไว้ในหน่วยความจำร่วม แล้วลงทะเบียนโมเดลนั้น; คืนค่าเป็นดัชนีใหม่ใน registry หรือรหัสของตัวโหลดที่เป็นค่าลบ (-1 manifest เสีย … -7 ความกว้างเฟรมผิด — ตารางเต็มอยู่ใน ai_model_staged.h) เรียกได้จาก task context เท่านั้น ห้ามเรียกจาก ISR หรือจาก callback ของ IPC pipe: mtb_ml_model_init() จองหน่วยความจำด้วย malloc จาก CM55 heap ก้อนเดียวกับที่ LVGL ใช้วาด และการลงทะเบียนจับ critical section (deepcraft_task.c:700-711); callback ของ IPC จึงต้องเข้าคิวการเรียกนี้ไว้ ต้องเรียก ai_engine_init() ก่อนหน้านี้ (แถวที่สร้างขึ้นต้องมี task ให้ทำงานอยู่บนนั้น — สำนวนที่ส่งมอบจริงเรียก init ซ้ำทันทีก่อนหน้า) ไม่มี ack event — การยืนยันคือการที่ ai_model_staged_count() เพิ่มขึ้น การตรวจสอบก่อนไว้ใจเกิดขึ้นที่ ai_model_staged.c:452-470; โหลดได้เฉพาะโมเดล IMU (window + quantize) เท่านั้น มี slot AI_STAGED_MAX ช่องต่อการบูตหนึ่งรอบ และไม่ถูกนำกลับมาใช้ซ้ำ ค่า -2 ยังครอบคลุมกรณีชื่อโมเดลซ้ำด้วย การโหลดไฟล์เดิม 2 ครั้งจึงดูเหมือนการชนเพดานทุกประการ
