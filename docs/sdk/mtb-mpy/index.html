Overview

The firmware SDK for the BENTO PSoC Edge kits gives you four things: six prebuilt module libraries you link against, a buildable template application that links them and boots into working firmware, tutorials grouped by feature, and an API reference with a code example on every function. One site: tutorials sit with their feature, the reference is last in each section.

What using it looks like

Tilt the board, the LED follows — a real accelerometer read driving a real PWM pin.

import sensors, gpio, time
sensors.init() # modsensors.c:523
red = gpio.led(2) # RGB_RED — modgpio.c:587
while True:
ax, ay, az = sensors.bmi270.acceleration() # modsensors.c:159
red.brightness(min(100, int(abs(ax) * 10))) # hardware PWM — modgpio.c:211
time.sleep_ms(100)

The whole program, with what to observe at each line, is A1 — From the zip to your first program.

Where the examples are

Every function's reference page carries an example. One lifted from shipped source has an Origin heading naming the file; one with no shipped call site is labelled Example (authored), so you always know which you are reading. The tutorials walk the real code in order, cited to file and line. Peripherals at a glance is tables only: every call, its file, its line and its BSP_HAS_* gate.

Building it
(cd lib && ./verify.sh) # signature + digest
for p in proj_cm33_s proj_cm33_ns proj_cm55; do (cd $p && make getlibs); done
make build -j && make program

The full sequence — the patch series, the mandatory power-cycle, the traps — is A1 — From the zip to your first program.

Sections, in reading order
  • Getting Started — the map of the SDK (which module owns which capability, and "I want to do X" → the chapter), then the path from the zip to your first program.
  • Architecture & Boot — the CM33_NS and CM55 boot walk-throughs and the three IPC contracts every page relies on.
  • Peripherals: Sensors & GPIO — the sensor bus and its lock, the six sensors, the auto-push task, LEDs and buttons, the QWA309 base board and the radar, with a quick-reference table of every call and its BSP_HAS_* gate.
  • Edge AI — select → confirm → start, parallel sets, stop/unload/staged models, diagnostics; then the Edge AI API reference.
  • Security / HSM — the OPTIGA chip-access discipline, enrolment and Protected Update end to end, the weak-symbol contract; then the TESAIoT HSM API reference.
  • Connectivity: WiFi & Cloud — WiFi, the two credential stores, MQTT and mTLS tutorials, with a map of where each API family is homed.
  • UI Pages & IPC — adding a screen and driving widgets over IPC; then the IPC Core and CM55 Core API references.
  • BLE / Bento Buddy — BLE bring-up, the single-RF rule, the NUS protocol surface; then the BLE NUS API reference.
  • Storage & Credentials — bento_storage, the C credential store and the heartbeat; then the storage/credentials API reference (the lfs_wifi_creds_* pages live here on both variants).
  • MicroPython Agent (BentoClaw) — TACP, the claw safety gates, sessions/transport/backends; then the MicroPython Secure API reference (mtb-mpy only).
  • Appendices — the signal atlas (decoding console lines, LED codes and fault markers), traps & anti-patterns, and the consumer-provided-symbols roster.
How the tutorials are written

Every chapter follows one form: Learning goal → the real firmware sequence (cited to the shipped file and line, with snippet blocks lifted from the shipped source where markers exist) → step-by-step, each step ending in a What you should observe callout that quotes only signals verified to print → traps → variant applicability. Variant forks are labelled panels inside a chapter; only whole-chapter exclusions differ between the two sets (docs/tutorials/<variant>/INCLUDED.list).
