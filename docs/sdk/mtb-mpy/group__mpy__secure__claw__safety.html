Detailed Description

Thirteen functions: the circuit breaker (claw_cb_*), the per-tool rate limiter (claw_rate_*) and the transport trust level (claw_trust_*). All are implemented in claw_safety.c, which is compiled into libbento_mpy.a and does not ship as source; the template ships only claw_safety.h. Every exemplar in this family is real shipped consumer code from template/bento_libs/claw/common/mpy/modbentoclaw.c.

Two idioms recur and are the whole contract of this family:

  • Initialisation goes through one idempotent function. Every shipped entry point calls bentoclaw_ensure_init() first; it runs claw_rate_init(), claw_cb_init(), claw_session_init() and the claw_rate_set() loop exactly once per soft reset. None of the three _init functions is called from anywhere else.
  • The gate order is fixed: circuit breaker → trust → rate check → rate record. The breaker is tested first because it is the cheapest and the one that blocks everything; the rate limiter is checked last and recorded only after all three gates pass.

State is plain module globals with no lock: the whole subsystem is driven from the single MicroPython task, and nothing here is ISR-safe.

Variant
mtb-mpy only (libbento_mpy.a is not linked under BENTO_HAS_MPY=0)
static void bentoclaw_ensure_init(void) {
if (s_module_inited) return;
claw_rate_init();
claw_cb_init();
claw_session_init();
/* Set per-tool rate limits from registry */
for (size_t i = 0; i < TOOL_COUNT; i++) {
if (s_tools[i].rate_per_min > 0) {
claw_rate_set(s_tools[i].name, s_tools[i].rate_per_min);
}
}
s_module_inited = true;
}

void claw_cb_init ( void )

Reset the circuit breaker to closed; called once, via bentoclaw_ensure_init() only.

Contract
Resets the circuit breaker to CLAW_CB_CLOSED with a zero error count. Called exactly once, via bentoclaw_ensure_init() only — no shipped code calls it directly, and calling it a second time while the breaker is open would silently discard an active cooldown. MicroPython task context; no locking; void, no error path.

◆ claw_cb_allow()

bool claw_cb_allow ( void )

Gate one of the fixed order: does the breaker permit execution?

Contract
Returns true when the breaker permits execution (CLAW_CB_CLOSED, or CLAW_CB_HALFOPEN allowing one test call), false while it is CLAW_CB_OPEN in cooldown. claw_cb_init() must have run — in shipped code via bentoclaw_ensure_init(). This is gate one of the mandatory order circuit breaker → trust → rate check → rate record; at every raise the caller increments its own s_error_count before the non-returning mp_raise_msg. Other shipped sites: the ask() guard (claw_https_connected()) and the TACP tool-exec path. Pure read; no locking; MicroPython task context.
Variant
mtb-mpy only (libbento_mpy.a is not linked under BENTO_HAS_MPY=0)
Example
The tool-call handler; the single most load-bearing snippet in the module, fixing the gate order and covering claw_trust_allows(), claw_rate_check() and claw_rate_record() in one place.
/* ...context: inside the tool-call handler; 'found' is the resolved tool entry ... */
/* Safety check: circuit breaker */
if (!claw_cb_allow()) {
s_error_count++;
mp_raise_msg(&mp_type_RuntimeError,
MP_ERROR_TEXT("circuit breaker open — cooldown active"));
}
/* Safety check: transport trust level */
if (!claw_trust_allows(found->risk)) {
s_error_count++;
mp_raise_msg(&mp_type_RuntimeError,
MP_ERROR_TEXT("tool risk exceeds transport trust level"));
}
/* Safety check: rate limiter */
if (!claw_rate_check(found->name)) {
s_error_count++;
mp_raise_msg(&mp_type_RuntimeError,
MP_ERROR_TEXT("rate limit exceeded for this tool"));
}
/* Record rate limit hit */
claw_rate_record(found->name);

◆ claw_cb_success()

void claw_cb_success ( void )

Record a success: resets the error count and closes the breaker.

Contract
Records a successful operation: resets the consecutive-error counter and closes the breaker (a half-open test call that succeeds closes it fully). claw_cb_init() via bentoclaw_ensure_init() first. Always paired with claw_cb_failure() on the same operation: the failure branch calls claw_cb_failure() before the non-returning mp_raise_msg, and the success branch calls claw_cb_success() on the fall-through path. Both are void with no error path. Only after claw_cb_success() does the shipped code append the assistant turn to the session (claw_session_add()).
Variant
mtb-mpy only (libbento_mpy.a is not linked under BENTO_HAS_MPY=0)
Example
The paired success/failure branches after claw_https_post().
/* ...context: inside bentoclaw_ask(), after claw_https_post() ... */
if (resp_len < 0) {
s_agent_state = CLAW_STATE_ERROR;
s_error_count++;
claw_cb_failure();
claw_ipc_send_ui(CLAW_UI_ERROR, "Backend error", 13);
snprintf(s_last_result, sizeof(s_last_result), "error");
claw_ipc_send_ui(CLAW_UI_LAST_RESULT, s_last_result, strlen(s_last_result));
mp_raise_msg(&mp_type_RuntimeError, MP_ERROR_TEXT("HTTPS request failed"));
}
/* ...context: inside bentoclaw_ask(), success path ... */
s_agent_state = CLAW_STATE_IDLE;
claw_cb_success();

◆ claw_cb_failure()

void claw_cb_failure ( void )

Record a failure BEFORE the non-returning raise; trips the breaker at three.

Contract
Records a failed operation: increments the consecutive-error counter and trips the breaker to CLAW_CB_OPEN (30 s cooldown) when the threshold of three is reached. claw_cb_init() first. Must be called before the non-returning raise — mp_raise_msg does not return, so a claw_cb_failure() placed after it never executes and the breaker never learns about the failure. Void, no error path; MicroPython task context. Shipped sites: the HTTPS ask() path and two TACP paths.
Variant
mtb-mpy only (libbento_mpy.a is not linked under BENTO_HAS_MPY=0)
Example
Same shipped snippet as claw_cb_success(): failure before raise, success on fall-through.
/* ...context: inside bentoclaw_ask(), after claw_https_post() ... */
if (resp_len < 0) {
s_agent_state = CLAW_STATE_ERROR;
s_error_count++;
claw_cb_failure();

◆ claw_cb_state()

claw_cb_state_t claw_cb_state ( void )

Status surface: the current breaker state (closed / open / half-open).

Contract
Status surface: returns the current claw_cb_state_t (CLAW_CB_CLOSED = 0, CLAW_CB_OPEN = 1, CLAW_CB_HALFOPEN = 2). The shipped consumer maps it through a three-entry name table with an explicit bounds guard ("unknown" for anything else) — copy that guard; the enum is returned by value from an archive you cannot inspect. Pure read, no locking, MicroPython task context; bentoclaw_ensure_init() precedes it.
Variant
mtb-mpy only (libbento_mpy.a is not linked under BENTO_HAS_MPY=0)
Example
bentoclaw_safety(), the one self-contained exemplar that serves claw_cb_state(), claw_trust_get() and claw_cb_cooldown_remaining().
static mp_obj_t bentoclaw_safety(void) {
bentoclaw_ensure_init();
mp_obj_dict_t *d = MP_OBJ_TO_PTR(mp_obj_new_dict(4));
static const char *cb_names[] = { "closed", "open", "half-open" };
claw_cb_state_t cb = claw_cb_state();
const char *cb_str = (cb < 3) ? cb_names[cb] : "unknown";
static const char *trust_names[] = { "none", "https", "usb" };
claw_trust_level_t trust = claw_trust_get();
const char *trust_str = (trust < 3) ? trust_names[trust] : "unknown";
mp_obj_dict_store(MP_OBJ_FROM_PTR(d),
MP_OBJ_NEW_QSTR(MP_QSTR_circuit_breaker),
mp_obj_new_str(cb_str, strlen(cb_str)));
mp_obj_dict_store(MP_OBJ_FROM_PTR(d),
MP_OBJ_NEW_QSTR(MP_QSTR_cooldown_ms),
mp_obj_new_int(claw_cb_cooldown_remaining()));

◆ claw_rate_check()

bool claw_rate_check ( const char * tool_name)

Gate three: is the tool under its per-minute limit? Checking does not consume budget.

Contract
Returns true when tool_name is under its per-minute limit, false when rate-limited. Checking does not consume the budget — the check and claw_rate_record() are separate calls against the same found->name, and a caller that checks without recording never counts. Gate three of the mandatory order (after the breaker and the trust level). Tools with no claw_rate_set() entry fall back to the default of 10 per minute. Pure read; no locking; MicroPython task context.
Variant
mtb-mpy only (libbento_mpy.a is not linked under BENTO_HAS_MPY=0)

◆ claw_trust_set()

void claw_trust_set ( claw_trust_level_t level)

Set the transport trust level; every HTTPS raise is paired with a USB reset.

Contract
Sets the transport trust level that claw_trust_allows() consults: CLAW_TRUST_USB (2, all tools), CLAW_TRUST_HTTPS (1, low and medium risk only), CLAW_TRUST_NONE (0, nothing). Raise trust to HTTPS before the connect attempt, so the level is already correct when the first tool call arrives; and every CLAW_TRUST_HTTPS set is matched by a CLAW_TRUST_USB reset on the failure branch and on the disconnect path (claw_https_disconnect()), so a failed connect never leaves high-risk tools enabled under a transport that should not have them. The level is a plain global with no lock. bentoclaw_ensure_init() has run at every shipped site.
Variant
mtb-mpy only (libbento_mpy.a is not linked under BENTO_HAS_MPY=0)
Example
Trust raised before claw_https_connect() and reverted inside the else.
/* ...context: inside bentoclaw_connect() ... */
claw_ipc_init();
claw_ipc_send_ui(CLAW_UI_STATUS_TEXT, "Connecting...", 13);
claw_trust_set(CLAW_TRUST_HTTPS);
bool ok = claw_https_connect(host, port, api_key);
if (ok) {
claw_ipc_send_ui(CLAW_UI_STATUS_TEXT, "Online (HTTPS)", 14);
claw_session_add(CLAW_ROLE_SYSTEM, "Connected to TESAIoT backend");
} else {
claw_ipc_send_ui(CLAW_UI_STATUS_TEXT, "Connect failed", 14);
claw_trust_set(CLAW_TRUST_USB);
}

The matching reset on disconnect:

static mp_obj_t bentoclaw_disconnect(void) {
claw_https_disconnect();
claw_trust_set(CLAW_TRUST_USB);
if (claw_ipc_initialized) {
claw_ipc_send_ui(CLAW_UI_STATUS_TEXT, "Offline", 7);
}
claw_session_add(CLAW_ROLE_SYSTEM, "Disconnected from backend");
return mp_const_none;
}
