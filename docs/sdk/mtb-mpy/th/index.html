SDK เฟิร์มแวร์สำหรับชุดบอร์ด BENTO PSoC Edge ให้สี่อย่าง ได้แก่ ไลบรารีโมดูลที่คอมไพล์ มาแล้วหกตัว ที่ลิงก์เข้ากับแอปพลิเคชันของผู้ใช้โดยตรง เทมเพลตแอปพลิเคชันที่ build ได้จริง ซึ่งลิงก์ไลบรารีเหล่านั้นและบูตขึ้นมาเป็นเฟิร์มแวร์ที่ใช้งานได้ Tutorial ที่จัดกลุ่มตามฟีเจอร์ และ คู่มืออ้างอิง API ที่มีตัวอย่างโค้ด กำกับทุกฟังก์ชัน ทั้งหมดอยู่ในเว็บไซต์เดียว โดย Tutorial อยู่คู่กับฟีเจอร์ของตน และคู่มืออ้างอิงอยู่ท้ายสุดของทุกส่วน

หน้าตาของการใช้งาน

เอียงบอร์ดแล้วให้ LED สว่างตาม — อ่านจาก accelerometer จริงและขับขาที่มี PWM จริง

import sensors, gpio, time
sensors.init() # modsensors.c:523
red = gpio.led(2) # RGB_RED — modgpio.c:587
while True:
ax, ay, az = sensors.bmi270.acceleration() # modsensors.c:159
red.brightness(min(100, int(abs(ax) * 10))) # hardware PWM — modgpio.c:211
time.sleep_ms(100)

โปรแกรมนี้ฉบับเต็ม พร้อมสิ่งที่ควรสังเกตทีละบรรทัด อยู่ที่ A1 — จากไฟล์ zip ถึงโปรแกรมแรก

ตัวอย่างอยู่ที่ใด

หน้าอ้างอิงของทุกฟังก์ชันมีตัวอย่างกำกับ ตัวอย่างที่ยกมาจากซอร์สที่ส่งมอบจริงมีหัวข้อ ที่มา ระบุไฟล์ ส่วนตัวอย่างที่ไม่มี call site ในของที่ส่งมอบมีหัวข้อ ตัวอย่าง (เขียนขึ้นเอง) กำกับตรง ๆ Tutorial เดินโค้ดจริงตามลำดับ พร้อมไฟล์และบรรทัด และ อุปกรณ์ต่อพ่วงโดยสรุป เป็นตารางล้วนของทุกการเรียก ไฟล์ บรรทัด และ gate BSP_HAS_* ของแต่ละตัว

การ build
(cd lib && ./verify.sh) # ลายเซ็น + digest
for p in proj_cm33_s proj_cm33_ns proj_cm55; do (cd $p && make getlibs); done
make build -j && make program

ลำดับเต็ม (patch series, การตัดไฟจ่ายไฟใหม่, ข้อควรระวัง) อยู่ที่ A1 — จากไฟล์ zip ถึงโปรแกรมแรก

Note
ชุดเอกสารนี้เป็นของแพ็กเกจ mtb-mpy (มี MicroPython VM) ชุดเอกสารของแพ็กเกจ ภาษา C ล้วนคือ mtb-only — โครงสร้างส่วนเดียวกัน URL สัมพัทธ์เดียวกัน หรือใช้ตัวเลือก variant ที่ส่วนหัวของหน้า
ส่วนต่าง ๆ ตามลำดับการอ่าน
  • เริ่มต้นใช้งาน — แผนที่ของ SDK (ความสามารถแต่ละอย่างเป็นของโมดูลใด และ "อยากทำ X ต้องเปิดบทไหน") จากนั้นเป็นเส้นทางจากไฟล์ zip ถึงโปรแกรมแรก
  • สถาปัตยกรรมและการบูต — การเดินตามลำดับการบูตของ CM33_NS และ CM55 และ ข้อกำหนดการเรียกใช้ของ IPC สามชุดที่ทุกหน้า (page) พึ่งพา
  • อุปกรณ์ต่อพ่วง: เซนเซอร์และ GPIO — บัสเซนเซอร์และ lock ของบัสนั้น เซนเซอร์ทั้งหกตัว auto-push task, LED และปุ่ม บอร์ดฐาน QWA309 และ radar พร้อมตารางอ้างอิงอย่างเร็วของทุกการเรียกใช้และ gate BSP_HAS_* ของแต่ละตัว
  • Edge AI — select → confirm → start, parallel set, การ stop/unload/staged โมเดล และข้อมูลวินิจฉัย จากนั้นเป็นคู่มืออ้างอิง API ของ Edge AI
  • ความปลอดภัย / HSM — ระเบียบการเข้าถึงชิป OPTIGA, การลงทะเบียนและ Protected Update ตั้งแต่ต้นจนจบ, ข้อกำหนดการเรียกใช้ของ weak symbol จากนั้นเป็นคู่มืออ้างอิง API ของ TESAIoT HSM
  • การเชื่อมต่อ: WiFi และคลาวด์ — WiFi, ที่เก็บข้อมูลรับรองสองแห่ง, Tutorial MQTT และ mTLS พร้อมแผนผังว่า API แต่ละตระกูลถูกจัดวางไว้ที่ส่วนใด
  • หน้า UI และ IPC — การเพิ่มหน้าจอและการสั่ง widget ผ่าน IPC จากนั้นเป็นคู่มืออ้างอิง API ของ IPC Core และ CM55 Core
  • BLE / Bento Buddy — การเปิดใช้งาน BLE, กฎ single-RF, ส่วนที่เรียกใช้ได้ของโปรโตคอล NUS จากนั้นเป็นคู่มืออ้างอิง API ของ BLE NUS
  • ที่เก็บข้อมูลและข้อมูลรับรอง — bento_storage, ที่เก็บข้อมูลรับรองฝั่ง C และสัญญาณชีพ (heartbeat) จากนั้นเป็นคู่มืออ้างอิง API ของ storage/credentials (หน้า lfs_wifi_creds_* อยู่ที่ส่วนนี้ทั้งสอง variant)
  • MicroPython Agent (BentoClaw) — TACP, safety gate ของ claw, session/ชั้นขนส่ง/backend จากนั้นเป็นคู่มืออ้างอิง API ของ MicroPython Secure (มีเฉพาะ mtb-mpy)
  • ภาคผนวก — แผนที่สัญญาณ (การแปลความบรรทัดคอนโซล รหัส LED และ marker บอกความผิดพลาด) กับดักและ anti-pattern และบัญชี symbol ที่ผู้ใช้ไลบรารีต้องจัดหาเอง
รูปแบบการเขียน Tutorial

ทุกบทใช้รูปแบบเดียวกัน คือ เป้าหมายของหัวข้อนี้ → ลำดับการทำงานจริงของเฟิร์มแวร์ (อ้างถึงไฟล์และบรรทัดที่ส่งมอบจริง พร้อมบล็อก snippet ที่ยกมาจากซอร์สที่ส่งมอบเมื่อมี marker กำกับไว้) → ทีละขั้น โดยแต่ละขั้นจบด้วยกล่อง สิ่งที่ควรสังเกต ซึ่งยกมาเฉพาะสัญญาณที่ตรวจแล้วว่าพิมพ์ออกมาจริง → กับดัก → variant ที่ใช้ได้ การแยกตาม variant แสดงเป็นแผงที่มีป้ายกำกับอยู่ภายในบท สิ่งที่ต่างกันระหว่างชุดเอกสารทั้งสองมีเพียงการตัดทั้งบทออกเท่านั้น (docs/tutorials/<variant>/INCLUDED.list)
