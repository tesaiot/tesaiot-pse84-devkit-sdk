J5 — The QWA309 base board: pots, buttons, RGB matrix, header
Peripherals: Sensors & GPIO » Tutorials
Variant
mtb-mpy only (libbento_mpy.a is not linked under BENTO_HAS_MPY=0)

All five modules in this chapter live in bento_libs/claw/kit-tesaiot-pse84-ai/mpy/, a directory that does not exist in the mtb-only package. The base board itself is the same hardware on both variants; on mtb-only you reach it through the PDL and through cm55_sensor_poll (The C entry points (both packages)).

Learning goal

After this chapter you can read the four knobs, the two buttons and the RGB matrix, and drive the expansion header. Two facts here are load-bearing and neither is guessable from the API: the knob-to-channel map is not identity, and one of the two buttons shares its pin with USB host power. Get either wrong and the code compiles, runs, and reports the wrong knob or kills the joystick.

The real firmware sequence

Everything is behind one flag. pots, buttons, rgbmatrix, header, can and shield are each wrapped in #if BSP_HAS_QWA309_BASEBOARD, which this board sets to 1 (bsp_features.mk:25). On a bare AI Kit SoM none of them is registered, and import pots raises ImportError — not a runtime error from a missing device.

The two cores split the base board by capability, not by device. The pots are read from CM33_NS straight out of the AutAnalog SAR result registers — no IPC, microsecond latency, which is what makes a 60 fps paddle possible (mod_qwa309_pots.c:5-15). The RGB matrix is on the CM55-owned header I2C bus, so every rgbmatrix.* call is a fire-and-forget IPC message and CM33 never touches that bus (mod_rgbmatrix.c:6-13). CapSense is likewise CM55's (The CapSense fork: one API, two backends). The buttons and the header are pure CM33_NS GPIO.

The knob map is not the identity

s_pots_knob_ch[] is { 5, 4, 6, 7 } (mod_qwa309_pots.c:55). Logical index 0 (VR1) reads SAR GPIO channel 5, and index 1 (VR2) reads channel 4. The reason, from the source: the QWA309 PCB routes P15.4 (channel 4) to the VR2 knob and P15.5 (channel 5) to VR1 — the first two traces are swapped on the board, verified on hardware. VR3 and VR4 are wired straight.

This table must stay in lockstep with s_pot_adc_ch[] in proj_cm55/modules/cm55_sensor_poll/cm55_sensor_poll.c:80, which carries the identical { 5, 4, 6, 7 } and the identical comment. The CM55 page compensated from 2026-07-31; this module shipped uncompensated, so pots.read(0) returned the knob silkscreened VR2 until it was fixed on 2026-08-20. If you ever change one of the two tables, change both, or the screen and the REPL will disagree about which knob the user is turning — and each will be internally consistent, which is what makes it hard to see.

The SAR is started by CM33_NS at boot, not by this module. init_potentiometer_adc() (proj_cm33_ns/main.c:142) runs Cy_AutAnalog_Init(&autonomous_analog_init) and Cy_AutAnalog_StartAutonomousControl(), gated on BSP_HAS_POTENTIOMETER, and is called at main.c:224. The BSP's design.modus supplies the config struct but init_cycfg_peripherals() does not call the init API — so if this step is removed, every channel reads 0 forever and nothing reports an error. The boot order that makes this work is B1 — CM33_NS boot walk-through; do not re-derive it here.

A zero is not proof of anything. An unconfigured channel also reads 0, which is why pots.ready() exists: it exposes the per-channel result-status gate, and all four channels must have produced a result in the last scan (mod_qwa309_pots.c:56-60). Use it for bring-up, not per frame.

There is a spike filter. The SAR occasionally glitches a sample to near zero. pots_read_channel() rejects a drop of more than 200 counts to below 50 once, and accepts the second consecutive low reading as the player really slamming the knob to the end stop (mod_qwa309_pots.c:66-89). The CM55 page uses the same rule so the two paths agree.

Two buttons, one of which is also USB power

s_btns[] (mod_qwa309_buttons.c:67-68): index 0 is SW4 on P17.5, index 1 is SW5 on P17.7, both active-low with MCU internal pull-ups, and both debounced in software with a 50 ms stable window.

Two things the header comment (mod_qwa309_buttons.c:8-22) records that the API cannot:

  • The names have a history. These are the production silkscreen names. Older documents call the same nets SW9/SW10, and the native GPIO and RGB page calls them SW5/SW6. Three naming schemes, one pair of buttons. buttons.name(n) is authoritative.
  • P17.5 is also the USB-host VBUS enable (usbh_config.c), and these nets are shared with DVP camera signals. Using the buttons and the USB joystick at the same time is not supported on this base board: the first buttons_hw_init() takes P17.5 for input. This is an accepted trade-off, not an oversight — but it means a single import buttons can stop a joystick working, and nothing will tell you.

Step by step

Step 1 — Prove the SAR is alive before trusting a reading

Example (authored — no shipped call site)
import pots
print(pots.count(), pots.ready())
print(pots.read_all())
What you should observe
4 True, then a 4-tuple of ints in 0..4095. ready() false means the SAR has not completed a scan of channels 4..7 — check that BSP_HAS_POTENTIOMETER=1 and that init_potentiometer_adc() still runs in main(). A tuple of four zeros with ready() true means four knobs at one end stop; a tuple of four zeros with ready() false means the converter never started. Distinguishing those two is the entire reason ready() exists.

Step 2 — Confirm the knob map with your hand

Example (authored — no shipped call site)
import pots, time
while True:
print(["%.2f" % pots.norm(i) for i in range(4)])
time.sleep_ms(200)
What you should observe
Turn the knob silkscreened VR1 and the first number moves. That is the fix working. If the second number moves instead, you are running a build whose s_pots_knob_ch[] is the identity map — and the CM55 pots page will disagree with you, which is the tell.

Step 3 — Read the two buttons

Example (authored — no shipped call site)
import buttons, time
print(buttons.count(), buttons.name(0), buttons.name(1))
while True:
sw4, sw5 = buttons.read()
if sw4 or sw5:
print("SW4" if sw4 else "", "SW5" if sw5 else "")
time.sleep_ms(50)
What you should observe
2 SW4 SW5, then one line per press with no bounce — the 50 ms stable window is inside buttons_sample(), so you do not add your own. buttons.pressed(n) is the single-button form; an index outside 0..1 raises ValueError.
Warning
Running this stops a USB joystick working until the next power cycle. P17.5 is the VBUS enable, and this code takes it for input. Decide which one the board is for.

Step 4 — Put something on the RGB matrix

Example (authored — no shipped call site)
import rgbmatrix as m, time
m.clear()
m.pixel(0, 0, m.RED)
m.pixel(15, 7, m.CYAN)
time.sleep(1)
m.score(42, m.GREEN)
time.sleep(1)
m.bar(3, 5, m.YELLOW)
time.sleep(1)
m.scroll("BENTO", m.WHITE, 80)
time.sleep(3)
m.scroll("") # stop the marquee
m.clear()
What you should observe
The DFR0522 panel follows each call. pixel() takes x 0..15 and y 0..7; score() shows 0..9999; bar() draws value of max. scroll() hands the text to a CM55 timer that runs the marquee in C — it returns immediately and keeps scrolling until you call scroll("").

Every one of these calls is fire-and-forget over IPC_CMD_UI_RGB_MATRIX and returns None. There is no acknowledgement and no error: if the panel is not plugged in, the calls still succeed and nothing lights up. Zero-caller module — every example here is authored.

Step 5 — Drive the expansion header

Example (authored — no shipped call site)
import header, time
header.gpio_out(0, 1) # P13.0 high
print(header.name(0), header.gpio_in(1))
header.pwm(3, 25, 1000) # P13.3 at 25% duty, 1 kHz
header.uart_write(b"hello\r\n") # SCB9, P15.1 TX, 115200 8N1
time.sleep_ms(100)
if header.uart_any():
print(header.uart_read(header.uart_any()))
What you should observe
Logical index 0..5 maps to P13.0, P13.3, P13.4, P13.5, P13.6, P13.7 (mod_qwa309_header.c:8-13). pwm() uses TCPWM0 counter 5 on P13.3, with P13.4 driven as its hardware complement — so a PWM on pin 3 takes pin 4 with it, and gpio_out(2, ...) afterwards will fight the peripheral. The UART is SCB9 at 115200 8N1, and it is a different UART from the console: what you write here does not appear in your terminal. Zero-caller module; authored example.

Two modules this chapter only points at

  • can (modcan.c:479) — init, send, recv, deinit, stats.
  • shield.motor_v2 (mod_shield_motor_v2.c:313) — speed, run, stop_all, and the stepper family stepper_attach, stepper_detach, stepper_rpm, stepper_step, stepper_stop, stepper_release, with the constants FORWARD/BACKWARD/BRAKE/RELEASE = 1..4 and SINGLE/DOUBLE/INTERLEAVE/MICROSTEP = 1..4.

Both are registered under the same base-board flag, and both are peripheral adjacent — they drive things plugged into the board rather than things on it. The Motor Shield page they pair with is off by default (bsp_features.mk:77), on the reasoning that most boards have no shield fitted and a menu that drives absent hardware is noise. Re-enable per build with ENABLE_PAGE_MOTOR_CTRL=1. Neither module has a caller anywhere in the shipped tree.

Traps

Warning
The knob map is {5, 4, 6, 7}, and it lives in two files. mod_qwa309_pots.c:55 and cm55_sensor_poll.c:80. Change one without the other and the REPL and the screen will each be consistently wrong in different directions.
pots.read(n) returning 0 is ambiguous until pots.ready() says the scan completed.
import buttons costs you the USB joystick. P17.5 is the VBUS enable and buttons_hw_init() claims it.
Do not trust three different sets of button names. SW4/SW5 is the production silkscreen; SW9/SW10 and SW5/SW6 appear in older material and in the native GPIO page. Ask buttons.name(n).
rgbmatrix cannot fail. Every call is fire-and-forget IPC. An unplugged panel produces silence, not an exception.
header.pwm(3, ...) also claims P13.4. The complement output is hardware, not a convention.
Do not add a second SAR owner. CM33_NS starts the converter and CM55 reads the same result registers; both are read-only consumers of a free-running conversion, which is why they coexist without arbitration (mod_qwa309_pots.c:11-15). Calling Cy_AutAnalog_Init() again from anywhere else breaks that.
