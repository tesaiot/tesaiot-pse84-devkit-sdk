สองเรื่องที่ควรรู้ก่อนออกแบบวงจรต่อ

  • Arduino header ไม่มีขาอนาล็อก — A0–A3 ไม่ได้ต่อ มีเพียง A4/A5 ซึ่งเป็นขา I²C

02

สองเส้นทาง คุณภาพเท่ากัน

TESAIoT Firmware Stack ส่งมอบเป็น project template สองแบบ เลือกตามวิธีทำงานของคุณ ไม่ใช่ตามระดับความสามารถ — ทั้งสองแบบใช้ไลบรารีชุดเดียวกัน ฮาร์ดแวร์ชุดเดียวกัน และเอกสารชุดเดียวกัน

ModusToolbox™

คอมไพล์เป็นเฟิร์มแวร์ ควบคุมได้ทุกไบต์

ModusToolbox™ คือชุดเครื่องมือพัฒนาอย่างเป็นทางการของ Infineon สำหรับ PSoC™ ประกอบด้วย BSP ของบอร์ด, ไลบรารีฮาร์ดแวร์, ตัวตั้งค่าอุปกรณ์แบบกราฟิก และคอมไพเลอร์ Arm GCC — โปรเจกต์ที่ได้เป็นภาษา C ล้วน คอมไพล์ลงทั้งสามคอร์

  • คุมเวลาได้ระดับไมโครวินาที — ไม่มีชั้นแปลภาษาคั่นระหว่างโค้ดกับฮาร์ดแวร์
  • แก้ค่าอุปกรณ์ด้วยเครื่องมือกราฟิก — นาฬิกา ขา GPIO และ peripheral ตั้งผ่าน Device Configurator
  • ดีบักระดับคำสั่ง — breakpoint, ดูรีจิสเตอร์, ไล่ทีละบรรทัดผ่าน KitProg
  • ใช้ RAM และแฟลชน้อยที่สุด — เหลือที่ให้โมเดล Edge AI มากที่สุด

เหมาะกับ: สินค้าที่ต้องผลิตจริง งานที่คุม latency งานที่แบตเตอรี่เป็นข้อจำกัด

ModusToolbox™ + MicroPython

เขียน Python บนบอร์ด เห็นผลทันทีที่กด Enter

ได้ทุกอย่างของเส้นทางแรก บวก MicroPython ที่ฝังอยู่ในเฟิร์มแวร์ตั้งแต่ต้น พร้อมโมดูลที่เราเขียนขึ้นเองสำหรับเซนเซอร์ จอ Wi-Fi, MQTT, HSM และ Edge AI — เชื่อมสาย USB แล้วพิมพ์คำสั่งคุยกับฮาร์ดแวร์ได้เลย

  • ไม่ต้องคอมไพล์ ไม่ต้อง flash — แก้แล้วรันทันที รอบการทดลองจากนาทีเหลือวินาที
  • REPL คุยกับบอร์ดสด ๆ — อ่านเซนเซอร์ทีละบรรทัดเพื่อหาสาเหตุปัญหา
  • ไฟล์ Python เก็บบนบอร์ด — ระบบไฟล์ 52 MB โค้ดอยู่กับอุปกรณ์ ไม่หายเมื่อถอดไฟ
  • ผสม C กับ Python ได้ — ส่วนที่ต้องเร็วเขียน C ส่วนที่ต้องแก้บ่อยเขียน Python

เหมาะกับ: การเรียนการสอน งานต้นแบบ การทดลองเซนเซอร์ และงานที่โจทย์ยังเปลี่ยนบ่อย

  • ~237,000 บรรทัด ของ C ที่เปิดให้อ่าน — ทุกหน้าจอ ทุกไดรเวอร์ ทั้ง BSP
  • 6 ไลบรารีสำเร็จรูป เปิดเผย API สาธารณะ 284 รายการ พร้อม api.txt ที่ตรงกับความจริง

03

ความปลอดภัยที่พูดเท่าที่ทำได้จริง

เราพิสูจน์บนบอร์ดจริง และเขียนเฉพาะสิ่งที่พิสูจน์แล้ว ส่วนที่ยังไม่บังคับใช้ เราบอกว่ายังไม่บังคับใช้

พิสูจน์บนฮาร์ดแวร์แล้ว

OPTIGA™ Trust M

  • สร้างคู่กุญแจภายในชิป — กุญแจส่วนตัวไม่เคยออกมานอกชิป
  • ขอใบรับรองผ่าน CSR และรับกลับมาทาง MQTT over TLS
  • Protected Update พร้อมการตรวจ manifest ในซิลิกอน ซึ่งล้มเหลวแบบปิด
  • Mutual TLS โดยกุญแจอยู่ในชิปตลอดการทำงาน

OPTIGA เป็นโมดูลเสียบ ไม่ได้บัดกรีบนบอร์ด — สั่งแยกและเสียบที่ที่อยู่ 0x30

ยังไม่บังคับใช้ — และเราเขียนไว้ตรง ๆ

สิ่งที่ยังเป็นข้อตกลง ไม่ใช่กลไก

  • การตรวจสิทธิ์การใช้งาน — ไม่ได้คอมไพล์เข้าอิมเมจใด ข้อจำกัดเชิงพาณิชย์เป็นสัญญา ไม่ใช่เทคนิค
  • ลายเซ็นโมเดล Edge AI — ตรวจจริง แต่ไม่บล็อก โมเดลที่ลายเซ็นไม่ผ่านยังโหลดได้
  • การจับคู่ BLE — ปัจจุบันเป็น Just Works ไม่บังคับการยืนยันตัวตน (BLE ปิดโดยค่าเริ่มต้น)
  • ใบรับรองจากโรงงานระบุตัวชิป ไม่ใช่ตัวอุปกรณ์ — การผูกตัวตนต้องทำที่ฝั่ง broker

04

Edge AI ที่รันได้ในวันแรก

เอนจินอยู่บน Cortex®-M55 คู่กับ Ethos™-U55 NPU มาพร้อมโมเดล DEEPCRAFT™ ที่ทำงานได้จริงตั้งแต่แกะกล่อง และช่องว่างให้คุณใส่ของตัวเอง

ช่องโมเดล 6 ช่อง

  • motionทำงาน
  • audioทำงาน
  • radarทำงาน
  • coughว่าง
  • alarmว่าง
  • sirenว่าง

สามช่องแรกมีโมเดลที่ส่งมาด้วย อีกสามช่องเว้นไว้โดยตั้งใจ — โมเดลสำเร็จรูปของ Imagimob อยู่ภายใต้สัญญาอนุญาตของเขา เราจึงไม่แจกจ่ายต่อ แต่เปิดช่องไว้ให้คุณนำมาใส่เองได้

สี่วิธีใส่โมเดลของคุณเอง

  1. ลงทะเบียนตอนรันไทม์ เรียก ai_engine_register() — ไม่ต้องใช้ช่องที่มีอยู่ ไม่ต้องคอมไพล์เอนจินใหม่
  2. Export จาก DEEPCRAFT™ Studio เขียนทับไฟล์โมเดลเดิม เปลี่ยนชื่อจุดเข้าใช้งานสี่จุด
  3. วางไลบรารีของคุณลงไป ตั้งชื่อตามรูปแบบ แล้ว Makefile จัดการลิงก์ให้เอง
  4. เขียน runtime เอง อะไรก็ได้ที่อยู่หลังฟังก์ชันสี่ตัวนั้น — TFLite หรือของคุณเอง

ทุกวิธีทำได้โดยไม่ต้องแตะโค้ดที่เราปิด และไม่ต้องรอไลบรารีชุดใหม่จากเรา

05

สิ่งที่นักพัฒนาไทยได้รับจริง

TESAIoT AIoT Foundation ไม่ได้ตั้งขึ้นเพื่อขายบอร์ด แต่เพื่อลดระยะทางระหว่างวิศวกรไทยคนหนึ่ง กับผลิตภัณฑ์ที่ขายได้จริง

ไม่ต้องเริ่มจากศูนย์

สามคอร์ IPC จอ LVGL พร้อมฟอนต์ไทย เครือข่าย TLS ระบบไฟล์ และ Edge AI ทำงานร่วมกันได้แล้วตั้งแต่ไฟล์แรก งานที่ปกติกินเวลาหลายเดือนก่อนจะได้เห็นผลลัพธ์แรก

เอกสารภาษาไทยที่เขียนสำหรับวิศวกร

838 หน้าสองภาษา ศัพท์เทคนิคคงไว้เป็นภาษาอังกฤษตามที่ใช้จริงในวงการ พร้อมตัวอย่างที่คอมไพล์ผ่าน ไม่ใช่โค้ดในเอกสารที่ลอกไปแล้วใช้ไม่ได้

เส้นทางสู่สินค้าจริง

โครงสร้างเดียวกันนี้รองรับตั้งแต่งานเรียน งานต้นแบบ ไปจนถึงการผลิต พร้อม HSM สำหรับตัวตนอุปกรณ์ และ Protected Update สำหรับการอัปเดตภาคสนาม

ความรู้ที่อยู่กับคนไทย

หลักสูตร ห้องปฏิบัติการ และการอบรมที่ใช้บอร์ดและ stack ชุดเดียวกันกับที่ใช้ทำสินค้า สิ่งที่ผู้เรียนฝึกในห้อง คือสิ่งเดียวกับที่ใช้ทำงานจริง
