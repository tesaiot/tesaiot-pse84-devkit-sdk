Appendix X — Traps and anti-patterns
Appendices
Variant
mtb-mpy and mtb-only

A compiled register. Every entry cites the line that proves it. Entries are numbered as in the design of record so chapters can refer to them by number.

1. CM55 printf is a silent no-op once libbento_edge_ai.a is linked

The archive defines printf and puts as deliberate no-op stubs (ai_engine.c:276-288; nm -S reports 8- and 4-byte T symbols). CM33_NS owns the UART and newlib stdio on CM55 would take a foreign lock and panic (ai_engine.c:270-275). Any printf in your own CM55 code produces nothing; you cannot link newlib stdio into this core. Treat the two symbols as a link-time ABI hazard, not API.

2. Never send a raw IPC_CMD_TOUCH_RESUME

CM55 treats it as an unconditional touch_disabled = false, cancelling another task's touch hold and producing OPTIGA_COMMS_ERROR (0x0102) on the shared bus (ipc_hsm_handler.c:1393-1405). Use the counted optiga_manager_touch_hold()/_release() pair.

3. optiga_chip_enter() is not an init check

It deliberately returns true when the manager was never initialised (tesaiot_optiga_manager.c:157-169). optiga_manager_lock() is the "is the manager up?" test; getting this backwards is the documented cause of several ungated-access defects.

4. Never ai_engine_resume_sensor() right after set_sensor_rate()

They share one CY_SECTION_SHAREDMEM buffer s_rate_msg; Cy_IPC_Pipe_SendMessage is asynchronous, so op=1's leading memset zeroes an in-flight op=2 and CM33 reads PAUSE (ai_engine.c:522-536). resume_sensor has no caller in shipped firmware.

5. Never gate a model fallback on ai_engine_active()

active() is s_current and lags the request by a whole cold-init. The recorded bug: "select Radar, Load, get Motion" (ai_engine.c:1868-1873). Guard on ai_engine_requested().

6. ai_engine_snapshot() in a parallel set loses detections

Last-writer-wins over one slot: "a cough detected at 0.94 is overwritten by three 'unlabelled' … The detection is not late, it is gone" (ai_engine.c:1876-1885). Use snapshot_model() per member.

7. Blind ipc_lcd_toggle_panel() inverts state

There is no idempotent set form; always guard with ipc_lcd_is_panel_visible() (ipc_core row 2, page_playground.c:167-188). Console and widgets are mutually exclusive.

8. Forgetting set_container(NULL) on page destroy is a use-after-free

lv_screen_load_anim(auto_del) frees the page's objects; a later IPC handler writes into them (ipc_core row 3, page_playground.c:342-349). NULL both containers on destroy, in the same order as the bind.

9. ipc_sensorhub_snapshot clears the changed flags

"Safe to call from any task context" but "Clears the 'changed' flags after reading" (ipc_sensorhub.h:66-67) — exactly one consumer per tick. The UI takes one snapshot at 33 ms and fans out.

10. UI list index is not the OPTIGA slot index

Resolve SSID → slot with wifi_saved_find() before any erase (wifi_connect_native.c:118-134); < 0 on miss.

11. The mtb-mpy credential flush never runs under a looping /main.py

wifi_creds_flush_if_dirty is called only at mpy_main.c:709 and :686 (REPL idle / exit). A program that never returns to the REPL never persists the credential; mtb-only writes immediately (sensor_auto_task.c:784-789 vs :828-854).

12. Retained Protected Update bundles replay

A retained bundle arrives on every connect; observed three times on 2026-08-07 silently redoing the previous run. trustm_current_correlation_id() == NULL means nothing is outstanding — discard (tesaiot_pu_ingest.c:752-768). At weak sites check the function pointer, then the string.

13. Unbounded I2C timeouts on the shared display bus starve CM55

The GFX task runs at MAX−1; a wedged clock-stretching device with a block-forever PDL timeout starved every lower-priority CM55 task. Use bounded timeouts (2 ms) on disp_touch_i2c_controller_context (cm55_sensor_poll.c:49-53).

14. PAGE_ID ordinals are ABI baked into libbento_ipc.a

page_id_ordinal_assert.c:22-25; lib/ipc_core/PROVENANCE.txt records PAGE_ID_PLAYGROUND == 7. A mismatch links cleanly and compares the wrong page. Add at the end; never renumber, never re-guard.

15. cfg.port is stored but unused

The MQTT port derives from tls_mode (mqtt_client_config.c:105-118). Editing port in /.tesaiot_config changes nothing.

16. Debugger attach parks a running mtb-only CM33 in a boot-ROM loop

main.c:278-287. The heartbeat exists because the variant has no instrument "that is not also the murder weapon". Flash, then power-cycle; do not attach to a running board.

18. Two unlocked credential writers can race the LFS file

modwifi.c:261-285 and wifi_init.c:261-302 read-modify-write the file directly without wifi_creds_lock and bypass g_boot_wifi_creds; there is no file-level lock outside mtb-only's bs_lock() (J8 thin-evidence #6).

19. Weak-consumed HSM symbols require pointer NULL checks

Six of the 18 tesaiot_hsm functions link only under ENABLE_OPTIGA_CLM=1 and are consumed as weak symbols: publish_csr, tesaiot_publish_protected_update, trustm_reset_state, trustm_current_correlation_id, trustm_requested_target_oid, trustm_requested_anchor_oid (A.5 preamble; refusal string at ipc_hsm_handler.c:2158-2161).

20. bento_buddy_auto_start_install is superseded

The legacy task skipped the WL_REG_ON / WCM init step that CYW55513 needs (main.c:344-347). No caller anywhere; use install_chip_power_then_ble().

21. Power-cycle after every flash

A debugger reset leaves the display dark, which looks exactly like a failed flash (shipped package READMEs: dist mtb-mpy :51-52, mtb-only :54; in-zip README :47-49). Taught in A1/A2 at the first checkpoint. Dark screen after flash = reset, not failure.

22. Cold-boot backlight (mtb-only)

The backlight can want a second unplug-replug on cold boot (dist mtb-only README :55). A dark screen after a power-cycle is not proof of a bad image.

23. A trailing space in bsp_features.mk silently drops the feature

Values must be a bare 1 or 0. The consuming Makefiles compare with ifeq ($(VAR),1), which is whitespace-sensitive, so BSP_HAS_CAPSENSE=1 (or an inline comment after the value) evaluates false and the feature's INCLUDES/CFLAGS vanish with no error anywhere — the build succeeds and the sensor is simply not there. The file states the rule itself (bsp_features.mk:28-30, restated at :55-57). Taught in The BSP flags, as this board sets them.
