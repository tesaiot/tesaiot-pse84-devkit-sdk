Detailed Description

ห้า symbol: การนำ BLE ขึ้นเมื่อมีการร้องขอกับการหยุดแบบ soft ตัวช่วย auto-start ของเดิม และคู่สะพาน IPC ระหว่าง CM33 กับ CM55 คอมไพล์เฉพาะเมื่อ ENABLE_PAGE_BENTO_BUDDY=1 (ค่าตั้งต้นคือ 0, proj_cm33_ns/Makefile:64, :305) ให้ build ใหม่หลังจาก make getlibs — ดู Flag gate (อ่านก่อน)

การประกาศ: ble_nus_lazy.h (start/stop/auto_start_install) และ bento_secure_undeclared.h (ipc_bento_buddy_rx_init — prototype ที่กู้กลับมา) ส่วน ipc_bento_buddy_send ไม่มี header ที่ส่งมอบจริงตัวใดประกาศไว้ (บันทึกไว้ใน bento_secure_undeclared.h) รายการของมันด้านล่างจึงยกตัวนิยามจาก archive มาแสดง

void bento_buddy_auto_start_install ( void )

task auto-start แบบครั้งเดียวของเดิม ไม่มีผู้เรียกที่ใดเลย — ถูกแทนที่ด้วยรูปแบบ chip-power แล้ว

ข้อกำหนดการเรียกใช้
สร้าง task แบบครั้งเดียวที่นำ BLE ขึ้นมาประมาณ 3 s หลัง scheduler เริ่มทำงาน เรียกจาก main() ก่อน vTaskStartScheduler ได้ ไม่มีผู้เรียกที่ใดเลย เส้นทางบูตที่ส่งมอบจริงแทนที่ฟังก์ชันนี้ไปแล้วอย่างชัดเจน (proj_cm33_ns/main.c:344-347): "the legacy task skipped the WL_REG_ON / WCM init step, which CYW55513 needs for BLE controller bring-up" — ตัวช่วยนี้นำ host stack ขึ้นมาทั้งที่ controller ยังไม่ได้รับไฟ ให้ใช้ install_chip_power_then_ble() (รูปแบบที่แสดงไว้ใต้ bento_buddy_request_start()) แทน

static void bento_ex_chip_power_then_ble_task(void *arg)
{
(void)arg;
vTaskDelay(pdMS_TO_TICKS(1500)); /* let the rest of boot settle */
/* Power the CYW55513 first — the step the legacy helper skipped. */
Cy_GPIO_Write(CYBSP_WIFI_WL_REG_ON_PORT, CYBSP_WIFI_WL_REG_ON_PIN, 1U);
/* WL_REG_ON to module-ready ≈ 5 ms; give the HCI controller firmware
* 50 ms to finish its internal power-up. */
vTaskDelay(pdMS_TO_TICKS(50));
int rc = bento_buddy_request_start(); /* 0 new, 1 running, -1 failed */
(void)rc;
vTaskDelete(NULL); /* one-shot */
}
__attribute__((used))

*

static StaticTask_t task_tcb;

task_stack, &task_tcb);
