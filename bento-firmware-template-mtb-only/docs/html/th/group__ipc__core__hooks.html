Detailed Description

dist/ipc_core/overridable.txt ระบุ symbol ไว้ 7 ตัวพอดี archive นิยาม symbol แต่ละตัวเป็น weak (ตรวจยืนยันโดยฝ่าย RED ด้วย nm : เป็น symbol ชนิด W ใน libbento_ipc.a) โปรเจกต์หนึ่งใส่ strong definition มาหนึ่งตัว แล้ว linker จะเลือกใช้ตัวนั้นโดยไม่แจ้งอะไร สิ่งเหล่านี้เป็นสิ่งที่ต้อง นิยามเอง ไม่ใช่สิ่งที่ เรียกใช้ — ทุก "hit" ของชื่อเหล่านี้ในเทมเพลตคือการนิยาม หน้าคู่มืออ้างอิงที่บอกให้ "call this" จึงเป็นสิ่งที่ผิด ตัวอย่างทุกตัวด้านล่างจึงเป็นการนิยามเพื่อเขียนทับด้วย strong definition ของเทมเพลตเอง อ้างอิงด้วยชื่อไฟล์และหมายเลขบรรทัด ไม่มีไฟล์นิยามเหล่านั้นไฟล์ใดมี marker ของ snippet อยู่ จุดต่าง ๆ จึงยกมาเป็นข้อความแทน

variant ที่ใช้ได้
mtb-mpy และ mtb-only (ทั้ง 7 ตัว)

ประกาศไว้ใน ipc_communication.h (shared include) ไม่ได้ประกาศไว้ใน header ของ archive เอง IPC service ที่อยู่ใน archive เรียกฟังก์ชันนี้เมื่อ CM33_NS ขอ IPC_CMD_CONTROLS_STATE (0xC6) ส่วนค่าปริยายชนิด weak ไม่รายงานอะไรเลย การเขียนทับ (override) ด้วย strong definition จะเติม out จากไบต์ capsense/pot ที่แคชไว้จากการวนอ่านเซนเซอร์ฝั่ง CM55 — คือฟิลด์บน GFX task ที่มีผู้เขียนรายเดียวตามที่หัวข้อ ipc_sensorhub_feed_capsense อธิบายไว้ — และคืนค่า false เมื่อ out เป็น NULL ให้นิยามฟังก์ชันนี้เฉพาะบนบอร์ดที่ CM55 เป็นเจ้าของบัสของ controls เท่านั้น

◆ ipc_ui_ext_dispatch()

bool ipc_ui_ext_dispatch ( uint32_t cmd,
const uint8_t * data )

ให้นิยามเอง ห้ามเรียก — dispatch ส่วนขยายของโปรเจกต์สำหรับ opcode ย่าน UI ที่ยังไม่มีตัวจัดการ

Project extension dispatch hook for UI-band IPC opcodes not handled by the built-in switch (weak default returns false / no-op). Called from process_ui_command() in GFX-task context, so implementations may touch the display / GFX resources (e.g. the QWA309 DFR0522 RGB matrix on display I2C).

Parameters
cmdThe IPC opcode (IPC_CMD_UI_* range).
dataPointer to the raw 128-byte IPC payload (ipc_msg_t.data).
Returns
true if the opcode was handled.
ข้อกำหนดการเรียกใช้
"Project extension dispatch hook for UI-band IPC opcodes not handled by the built-in switch (weak default returns false / no-op). Called from \c process_ui_command() in GFX-task context, so implementations may touch the display / GFX resources" (ipc_ui.h) data ชี้ไปที่ IPC payload ดิบขนาด 128 ไบต์ ให้คืนค่า true เมื่อ opcode นั้นถูกจัดการแล้ว โปรเจกต์หนึ่งอาจเขียนทับฟังก์ชันนี้ได้ ครั้งเดียว เมื่อมีหลายคุณสมบัติอาศัย hook เดียวกัน ให้ต่อกันเป็นสายจาก strong definition เพียงตัวเดียว ตามที่เทมเพลตทำ

uint16_t ipc_ui_platform_diag ( uint32_t * out,
uint16_t max_words )

weak hook ที่ strong definition ของมันส่งมอบมาใน libbento_cm55.a — เป็นตัวเข้าถึงข้อมูลวินิจฉัย (diagnostics) ของจอแสดงผลขนาด 10 เวิร์ดที่รองรับอย่างเป็นทางการ

ข้อกำหนดการเรียกใช้
ต้องมี max_words >= 10 (มิฉะนั้นคืนค่า 0) และคืนมา 10 เวิร์ด ได้แก่ สถานะ DC IRQ, จำนวนนับของ DC frame / underflow / bus-error, จำนวนครั้งที่ GPU กู้คืน, ตัวนับ flush start / ready / timeout, ค่าสูงสุดที่ stack ของ GFX task เคยใช้ และเปอร์เซ็นต์เวลาว่าง นี่คือเส้นทางเข้าถึงจากภายนอกที่รองรับอย่างเป็นทางการสำหรับ g_tesaiot_display_diag ของ display controller — ให้อ้างอิงและใช้งานผ่านตัวเข้าถึงนี้ ไม่ใช่ผ่านตัว struct เปิดออกให้ MicroPython ในชื่อ ui._diag() (เฉพาะ mtb-mpy ส่วนโค้ด C บน mtb-only เรียกได้โดยตรง) archive มีเพียง weak stub เท่านั้น ส่วน strong definition ส่งมอบมาภายใน libbento_cm55.a โปรเจกต์ที่ใช้ display controller ที่ส่งมอบมาจึงมีอยู่แล้ว
