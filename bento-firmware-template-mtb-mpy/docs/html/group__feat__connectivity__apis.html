Where the APIs live
Connectivity: WiFi & Cloud

The connectivity chapters teach APIs that are homed in other sections' modules — no module is reparented here, because no connectivity module exists (the C-chapter APIs live in cm55_core, the credential stores, ble_nus and shipped template source):

  • wifi_saved_* — the CM55 saved-networks list over the OPTIGA store, taught in C2 — WiFi from the UI over IPC — homed with the CM55 Core reference, WiFi saved networks (OPTIGA store).
  • lfs_wifi_creds_* — the LittleFS boot credential store, taught in C1 — WiFi: the two credential stores and boot auto-connect — homed with Storage & Credentials, WiFi credentials store (same home on both variant sites).
  • lfs_load_wifi_creds / lfs_save_wifi_creds / app_wifi_* — the C-side WiFi glue overridables: homed with the BLE NUS reference, WiFi overridables (implement, don't call).
  • MQTT and mTLS — not a prebuilt module at all: the pipeline ships as template source (tesaiot_mqtt/ — mqtt_task.c, mqtt_client_config.c, subscriber_task.c, publisher_task.c, mqtt_mtls_setup.c), quoted directly by C3 — TESAIoT cloud: config file → MQTT task → broker and C4 — mTLS: the OPTIGA-backed TLS identity.
