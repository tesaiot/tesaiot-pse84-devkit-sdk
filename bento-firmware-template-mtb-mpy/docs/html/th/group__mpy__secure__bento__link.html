Detailed Description

5 symbol: registry ของ bento_link (bento_link_register(), bento_link_get(), bento_link_at()) และจุดเข้า 2 จุดของ backend "ipc" ที่ส่งมอบมา (bento_link_ipc_init(), bento_link_ipc_query) เขียนไว้ใน bento_link.c และ bento_link_ipc.c คอมไพล์รวมอยู่ใน libbento_mpy.a ไม่ได้ส่งมอบมาเป็นซอร์ส bento_link.h ประกาศฟังก์ชันของ registry ไว้ 3 ตัว; bento_secure_undeclared.h เก็บ prototype ของ bento_link_ipc_init() ที่กู้กลับมา และบันทึกไว้ว่า bento_link_ipc_query() ไม่มีคำประกาศอยู่ที่ใดเลยในทรีนี้ — ผู้ใช้ไลบรารีเป็นผู้เขียน extern ขึ้นเอง

ตัวอย่างอ้างอิงที่ส่งมอบมาคือ template/bento_libs/claw/common/mpy/moddeepcraft.c และลำดับที่มันบังคับไว้คือข้อกำหนด: bento_link_ipc_init() → bento_link_get("ipc") → ตรวจ NULL → ต่อ bento_link_t ที่ได้คืนมาเข้ากับ adapter ของ DEEPCRAFT™

variant ที่ใช้ได้
mtb-mpy เท่านั้น (ไม่มีการลิงก์ libbento_mpy.a เมื่อ BENTO_HAS_MPY=0)

bento_link_t * bento_link_at ( uint32_t index)

ไล่รายการใน registry; คืน NULL เมื่อเลยรายการสุดท้าย

Enumerate registered backends: index 0..n-1, NULL past the end.

ข้อกำหนดการเรียกใช้
ไล่รายการใน registry: ดัชนี 0 ถึง n-1 คืน backend หนึ่งตัว และคืน NULL เมื่อเลยรายการสุดท้าย ให้วนตั้งแต่ 0 ถึง BENTO_LINK_MAX_BACKENDS แล้วหยุดที่ NULL ตัวแรก — registry เก็บเรียงชิดกันไม่มีช่องว่าง NULL จึงหมายความว่า "ไม่มีอีกแล้ว" เป็นที่มาของข้อมูลให้ deepcraft.links() ฝั่ง Python ไม่มีการจับ lock; ทำงานใน task context
variant ที่ใช้ได้
mtb-mpy เท่านั้น (ไม่มีการลิงก์ libbento_mpy.a เมื่อ BENTO_HAS_MPY=0)

deepcraft_links()
static mp_obj_t deepcraft_links(void)
{
ensure_inited();
mp_obj_t items[BENTO_LINK_MAX_BACKENDS];
uint32_t n = 0;
for (uint32_t i = 0; i < BENTO_LINK_MAX_BACKENDS; i++) {
bento_link_t *l = bento_link_at(i);
if (l == NULL) {
break;
}
items[n++] = mp_obj_new_str(l->name, strlen(l->name));
}
return mp_obj_new_tuple(n, items);
}

Register a backend (called once from each backend's init).

ข้อกำหนดการเรียกใช้
เป็น API สำหรับผู้เขียน backend ไม่ใช่ API สำหรับแอปพลิเคชัน backend ของ transport จะลงทะเบียนโครงสร้างฐาน bento_link_t ของตัวเองเพียงครั้งเดียว จากฟังก์ชัน init ของตัวเอง ก่อนที่ผู้ใช้ไลบรารีรายใดจะ bento_link_get() มันได้ — แบบที่ใช้จริงในของที่ส่งมอบคือ backend "ipc" ที่ลงทะเบียนตัวเองอยู่ภายใน bento_link_ipc_init() registry เก็บได้มากที่สุด BENTO_LINK_MAX_BACKENDS (4) รายการ; ค่า false หมายถึงเต็มหรือซ้ำ และ backend ต้องรายงานว่าตัวเองใช้งานไม่ได้ ห้ามวนลองใหม่ callback รับข้อมูลที่ลงทะเบียนผ่านโครงสร้างฐานนี้ ต้องถูกส่งมอบนอกบริบทของอินเทอร์รัปต์ (ISR → คิว → task ที่ทำหน้าที่ส่งมอบ) ตามที่ bento_link.h กำหนด ไม่มี call site ในเทมเพลตเลย; ผู้เรียกรายเดียวอยู่ภายใน archive
