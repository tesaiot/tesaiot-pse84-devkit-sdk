H1 — TACP: the IDE wire protocol
MicroPython Agent (BentoClaw) » Tutorials
Variant
mtb-mpy only (libbento_mpy.a is not linked under BENTO_HAS_MPY=0)

This chapter is excluded from the mtb-only documentation set: that variant has no REPL and no TACP, which is why the BENTO IDE cannot flash it (variants/mtb-only.mk ~:19-20).

Learning goal

Know the three rules of TACP: initialise once per soft reset, pump the UART inside every wait, and frame every response with its real length. Know the ISR escape hatch that exists for the day a runaway /main.py starves the pump.

Real firmware sequence

Init, once per soft reset. tacp_init() clears the ring buffer, the state machine and the UART FIFO so stale bytes cannot cause double resets:

/* ...context: inside the MicroPython task, at the soft_reset label ... */
soft_reset:
/* Clear TACP ring buffer, state machine, and UART FIFO on every
* soft reset so stale bytes don't cause double-resets. */
tacp_init();
/* Peek at safe-boot flag early so g_is_safe_boot is correct before
* check_boot_mode() runs later. Defensive: if any code path calls
* tacp_poll_uart() during init, the TACP handler sees the right value.
* The flag is NOT consumed here — check_boot_mode() handles that. */
g_is_safe_boot = (s_safe_boot_once_flag == MPY_SAFE_BOOT_MAGIC);

The pump. tacp_poll_uart() is a pump, not a predicate — its return value is discarded at all seven template sites. It runs in MicroPython task context and is placed inside every wait loop:

/* ...context: inside the UI IPC response wait loop ... */
mp_uint_t deadline = mp_hal_ticks_ms() + timeout_ms;
while (!ui_ipc_resp.ready) {
if ((mp_int_t)(mp_hal_ticks_ms() - deadline) >= 0) break;
tacp_poll_uart();
MICROPY_EVENT_POLL_HOOK;
}

The FreeRTOS-flavoured variant pairs it with vTaskDelay(pdMS_TO_TICKS(1)):

/* ...context: inside the joystick IPC response wait ... */
for (int w = 0; w < 50 && !js_ipc_response.ready; w++) {
tacp_poll_uart();
vTaskDelay(pdMS_TO_TICKS(1));

Framing a response. tacp_claw_respond() takes payload_len as the actual snprintf return, cast to uint16_t — never strlen of a truncated buffer:

static void claw_respond(uint8_t sub_cmd, const char *payload, uint16_t payload_len) {
tacp_claw_respond(sub_cmd, payload, payload_len);
}
static void claw_respond_err(const char *msg, uint16_t msg_len) {
tacp_claw_respond(TACP_CLAW_ERROR, msg, msg_len);
}
/*******************************************************************************
* READY frame — sent once at boot to announce firmware readiness.
* IDE listens for this instead of polling STATUS with delay+retry.
******************************************************************************/
void bentoclaw_send_ready(void) {
bentoclaw_ensure_init();
claw_ipc_init();
int n = snprintf(s_work_small, sizeof(s_work_small),
"{\"fw\":\"%s\",\"board\":\"%s\",\"tools\":%u,\"proto\":2}",
BENTOCLAW_VERSION, MICROPY_HW_BOARD_NAME, (unsigned)TOOL_COUNT);
tacp_claw_respond(TACP_CLAW_READY, s_work_small, (uint16_t)n);
/* Push initial stats to CM55 LCD so it shows real tool count immediately */
claw_ipc_send_stats();

The TACP_CLAW_READY frame is sent only after tacp_init(), mp_init(), the VFS mount and boot/main.py (mpy_main.c:697-703). Frames are binary; text is never mixed into the stream (modbentoclaw.c:1967-1971).

The ISR escape hatch. From an IPC ISR, guarded BENTO_HAS_MPY, for when /main.py loops and starves tacp_poll_uart():

/* ...context: inside the sensor-ctrl IPC ISR callback ... */
if (msg->cmd == IPC_CMD_DELETE_MAIN_PY) {
/* Graceful path: polled by tacp_poll_uart() in task context (works when
* the MP loop is alive, e.g. at the REPL). */
s_delete_pending = true;
/* Robust path: break the script + force a MicroPython soft reset DIRECTLY
* from this IPC ISR, so the Delete button works even when a runaway
* /main.py loop monopolises the CPU and starves tacp_poll_uart(). The
* soft reset keeps SRAM (s_delete_main_flag) intact -> boot removes
* /main.py. ISR-safe (no allocation, no hard reset). Ported from
* Game-libraries 8a0689a (HW-verified on Eva). */
#if BENTO_HAS_MPY
tacp_request_delete_main_from_isr();
#endif /* no VM: there is no /main.py to delete */

Step by step

Step 1 — See the READY frame

Flash, power-cycle, open the BENTO IDE on the board's port.

What you should observe. The IDE reports the board ready. On the raw console you will have seen [MPY] GC heap u KB @ p in s (mpy_main.c:552-554) before that; the READY frame itself is binary and is not printed.

Step 2 — Prove the pump is in the wait

>>> import time
>>> while True: time.sleep_ms(100)

What you should observe. The IDE's stop/reset still works — time.sleep_ms goes through MICROPY_EVENT_POLL_HOOK, which is where the pump lives. A busy loop that never yields (no sleep, no poll hook) does not pump, and the IDE loses the board until the ISR escape hatch or a hard reset.

Step 3 — Read the ring buffer (authored)

tacp_ring_buf_read() and tacp_ring_buf_readable() are exported with no caller anywhere (definitions tacp.c:885/:889). Their example is authored and labelled as such in the mpy_secure reference; treat them as inspection aids, not part of the shipped protocol path.

Traps

Warning
payload_len must be the real length. A strlen on a buffer that snprintf truncated frames the wrong byte count and desynchronises the IDE.
tacp_poll_uart() before tacp_init() reads an uninitialised ring; the init idiom runs once per soft reset from mpy_main.c:567-576.
A looping /main.py also blocks credential persistence. The deferred credential flusher runs only at mpy_main.c:709 and :686, so a program that never returns to the REPL never saves (Appendix X #11).

Variant box

mtb-mpy only. On mtb-only the IDE cannot reach the board; the only console signal is [HB] t=lus tasks=u.
